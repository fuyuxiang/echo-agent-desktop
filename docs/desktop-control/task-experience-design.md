# 电脑操作的任务体验设计

评审前基线：2026-10-24 通用执行优化已实测通过。MiniMax 在 macOS 完成显式新建、精确输入、保存、暂停与自然语言继续：48.653 秒 / 9 次调用；Safari 原生输入与文件选择：82.821 秒 / 15 次调用。确认卡为 0、保存面板重开为 0；Safari 仍有一次窗口变化后的引用刷新及一次输入读回重试。完整证据与中间轮退步见 validation.md。

## 产品判断

用户委托的是一个结果，而不是一套自动化协议。当前界面把聊天生成、电脑执行、任务授权三个内部机制作为独立的可操作状态暴露给用户，导致“发送继续但后台仍暂停”“恢复后还要发送消息”“再点一次任务授权”等步骤。单纯把按钮改名或合并位置，不能解决这个心智模型的问题。

正常路径应是：提出任务，系统执行，拿到经核验的成果。用户用“停一下”“继续保存”等自然语言控制同一个任务。电脑能力是执行手段，不应要求用户先理解模式或工具名称。

## 默认交互

- 用户明确要求在某个应用中填写、编辑、保存等，即委托执行整个任务；任务内观察、切换应用、原生控件、坐标后备、输入和保存连续执行，不再逐步确认，也不根据应用名称或按钮关键词机械弹窗。
- 系统自行选择文件接口、原生控件或截图后备；不要求用户选择 AX、截图、窗口、引用或焦点策略。
- 初次缺少 macOS/Windows 系统权限时，只提供必要的一次引导；系统权限不能通过模型或脚本代授。
- 正常执行只显示一句结果导向的进度，例如“正在保存文稿”。不常驻“操作电脑、问号、暂停说明、更多、继续、结束”等一整组专用工具栏。
- 保留现有统一停止入口作为随时可用的退出方式。停止同时作用于模型和实体桌面，不能只停生成而让键鼠继续。
- 暂停后用户说“继续”“接着保存”，由可信客户端控制层恢复同一任务，再继续模型执行；不要求额外点按钮、重新发送同一句话或重复授权。
- 任务完成时提供真实产物与保存位置；“调用成功”不等于“成果完成”。

“继续”的授权边界：必须来自用户直接输入，并能对应到当前任务及此前范围。网页、文档、工具输出中的“继续”或模型自己的话都不能触发恢复。用户消息中引用、讨论“继续”也不能被误认为控制指令。多任务或意图含糊时，只澄清必要的任务选择。

## 权限与确认

| 情况 | 默认行为 |
| --- | --- |
| 明确任务内的观察、定位、切换窗口、填写文本、保存到指定的新文件 | 连续执行，不按步骤弹窗 |
| 用户暂停后明确说继续同一任务 | 作为新的用户恢复意图，重新建立该任务执行授权，一次完成恢复和续做 |
| 应用重启或系统休眠恢复 | 保留任务与进度，等待用户明确继续；不能在加载历史时自行发送键鼠 |
| 首次需要操作未获系统授权的设备能力 | 一次清楚的系统设置引导，授予后从中断点续做 |
| 完成任务确实需要原请求未包含的关键选择 | 只问缺少的信息，用户的回答直接接续任务，不另加授权步骤 |
| 未被原请求明确授权的外部发送、付款、破坏性删除或覆盖 | 在执行前展示目标、影响及必要内容，取得针对性的确认 |
| 操作返回未知结果 | 先观察实际状态，不能盲目重放发送、付款、保存等动作 |

确认保护的是任务范围和实际风险，不应机械等同于“所有桌面写操作”。用户此前选择的“暂停/重启撤销授权”仍有效：恢复前旧执行 token 与授权均无效；可信用户的明确继续指令产生新的、同任务同范围授权，而不是静默保留旧授权。

## 一套任务状态

对用户只有运行中、等待必要输入、已暂停、已完成、无法完成等任务状态。聊天流和桌面执行从同一个任务生命周期派生，不能各自维护互相矛盾的恢复开关。

内部仍保留独立的权限校验、原生对象身份、执行租约与取消边界。这些约束由任务控制器协调，对话模型没有自我恢复或自我授权接口。

暂停必须记录原因，例如用户接管、系统桌面不可用、应用重启、验收期限。当前五分钟验收脚本会暂停任务，却被通用文案解释成“用户接管”，属于测试机制与产品状态表达混淆；生产任务不能照搬这个隐藏的验收时间限制。验收停止应明确记录验收原因，不能让用户为测试脚本的时限来回恢复。

模型输出结束不一定等于任务结束：询问必要信息、阶段性反馈和等待用户修改都可能只是同一任务的一部分。只有目标结果得到核验、用户取消，或明确失败时，才结束任务生命周期。

## 错误处理与进度

窗口、焦点、弹出的系统面板、过期引用和控件提供方异常优先在执行层恢复，不把内部错误直接转换成“请你再点继续”。恢复必须重新观察原目标，不在新窗口或其他账户上猜测操作。

只有确需用户处理时才打断，例如解锁设备、选择一个同名文件、确认覆盖已有内容。给出一个具体问题或下一步，避免让用户理解工具协议。不能把某个应用的 AX API 不可用误报为整个应用权限被撤销。

进度描述用户结果：“已填入正文，正在保存到指定目录”；失败描述具体未完成项：“正文已保留，文件尚未保存”。截图、原生控件探测及工具参数留在可展开的执行详情，不占用主任务区。

## 实施顺序与验收

1. 统一任务暂停/恢复/授权事件，先消除状态不一致。
2. 将可信用户的自然语言继续接入控制层，不经模型自我授权；加载会话和一般闲聊不触发恢复。
3. 移除正常路径上的专用电脑控制工具栏，复用现有统一停止入口；高级诊断放进执行详情。
4. 电脑服务只校验当前任务的用户执行意图及执行租约；移除按应用名称、按钮关键词和坐标后备的机械审批。关键决定由任务层提出具体问题，不要求用户逐步监督。
5. 沿真实 Runtime 验证 TextEdit 保存、Finder、本地页面、Electron、系统文件选择及跨应用暂停恢复，不以界面原型或模拟测试冒充操作成功。

验收重点：明确电脑任务的正常路径无需额外控制按钮；普通任务内操作无逐步确认；一次自然语言继续能恢复并续做；停止后不再派发后续实体输入；用户改动保留；权限失败只解释真实缺口；最终文件可独立读取并与用户要求一致。真实结果按场景分别记录；本轮四项流程已通过，其他应用及 Windows 实机不据此类推。

## 当前实现边界

执行效率由通用操作单元承担：`computer_context` 优先呈现输入框、可操作目标和内容，空结构容器在紧凑视图中省略，完整结构仍可通过 snapshot 查询。引用使用短句柄；只有原生对象、窗口/文档上下文和实际控件内容未改变时，才在新观察后沿用。暂停、目标移除、内容改变、文档切换或观察失败都不能靠旧句柄恢复执行权。

已打开的系统文件面板使用 `computer_file_dialog` 准备路径。执行器完成“前往目录/文件 → 键盘输入 → 精确读回 → 返回原面板 → 保存时填写文件名”，每步可取消，过程不创建文件、不打开或重开面板、不点击最终提交按钮。模型从返回的当前状态点击实际提交按钮并核验结果，不需要用户在旁监督。首版识别 macOS 标准系统面板，按系统控件身份处理，不按宿主应用名称分支；其他平台和自绘文件面板保留已有原生/截图路径，不能据此声称已实测通过。

可信 `agent_send` 的用户展示文本用于任务意图识别；引用、附件内容和 MCP 输出不进入控制命令解析。明确电脑请求自动切换真实 Runtime 工具配置，授权同一任务。任务描述只用于保留用户范围和恢复上下文，不是操作系统沙箱；后台不靠名称子串逐步决定是否弹窗。原生对象身份、前台窗口、保护字段、结果读回和取消令牌仍由执行器校验。浏览器独立的网络/上传策略和其他 MCP 权限沿用现有行为。

## 2026-10-24 评审后的交互修正

任务授权只在直接的桌面执行请求中建立；代码讨论、否定指令、引用和普通办公文件生成保留原有路径。续做支持带动作与补充要求的自然表达，保存路径、文件名及可信回答与原任务一起保存。尚无任务的普通路径回答不能自行开启电脑操作。

暂停状态提供一个可选“继续任务”入口，点击即发送一次可信继续消息；用户也可直接输入续做要求。正常运行不增加专用工具栏，生成间隙保留暂停入口。系统权限、桌面不可用、用户停止、重启与请求失败分别解释，拒绝发送时保留暂停状态。

这些修正对应新的源码回归；本页此前的实际任务耗时、调用数和二进制证据不因此自动更新。
